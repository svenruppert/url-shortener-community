# Release 00.22.00 — jCustos legacy-store migration guard

_2026-11-01_

A focused follow-up to 00.21.00 for the production migration off the
jSentinel-era data layout. This repository is the **Community Edition**
(EUPL-1.2).

## jCustos framework-store migration (startup guard)

Before the jCustos rebrand the security-framework store (audit trail,
sessions, credential records) lived in
`<data>/jsentinel-rest/jsentinel-store`; jCustos opens it under
`jcustos-store`. Starting the jCustos binary on a jSentinel-era data set
therefore left the old store orphaned and EclipseStore silently created a
fresh, empty one next to it — the audit trail restarted at genesis and the
credential records (including the API-key mapping the MCP service
authenticates with) became unreachable, **with no log entry**.

The old records were serialized under `com.svenruppert.jsentinel.*`; jCustos
reads `eu.jsentinel.jcustos.*` and ships no legacy mapping across the rebrand,
so the binary store cannot be adopted. The startup now detects an orphaned
`jsentinel-store`, logs a clear warning (what does not carry over, and to
re-issue the MCP API key) and archives it aside to
`jsentinel-store.retired-<UTC>` so the condition cannot recur silently.
Verified against a copy of the real production data.

**What carries over on the jSentinel → jCustos upgrade:** users and links
(stored under application classes that were never renamed) migrate cleanly via
EclipseStore schema evolution. **What does not:** the audit trail and the
jCustos credential records / API-key mapping — re-issue API keys after the
upgrade; the raw old store stays intact in the data backup.

This is a temporary shim for the single existing installation and will be
removed once that installation has migrated.
